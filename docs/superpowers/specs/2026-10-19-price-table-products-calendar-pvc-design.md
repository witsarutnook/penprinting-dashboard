## 1. เจตนา — ทำไม / ทำไมตอนนี้

ใกล้ปีใหม่ ลูกค้าจะถามเรื่อง **ปฏิทิน** เข้ามาใน LINE เยอะ และ **บัตร PVC** ก็เป็นคำถามประจำ ทุกวันนี้คุณนุ๊ก/ทีมตอบด้วยการส่ง **รูปตารางราคา** ที่ทำไว้แล้ว 4 ใบ (ปฏิทินจีน · ปฏิทินตั้งโต๊ะ 6x8 · ปฏิทินแขวน · PVC Ribbon) ให้ลูกค้าดูเอง

ต้องการให้ **น้อง PP ทำแทนได้ทั้งสองอย่าง**:
1. **ส่งรูปตารางราคาใบเดียวกับที่ทีมส่งเอง** ให้ลูกค้าในแชต (LINE + Messenger)
2. **รู้ตัวเลขในตาราง** จนตอบราคาต่อชุด/ต่อใบ + ราคารวม ตามจำนวนที่ลูกค้าขอได้ รวมถึงจำนวนที่ไม่ตรงขั้นในตาราง

ทั้งสองอย่างเกิด **ในโหมด AI เท่านั้น** — นอกโหมดแค่ "ชี้ทาง" ให้กดปุ่มเข้าโหมด (คุณนุ๊กเลือก: กลัวลูกค้างงถ้าบอทส่งรูปแล้วเงียบ)

## 2. Goals / Non-goals / Anti-goals

**Goals**
- ลูกค้าในโหมด AI ถาม "ปฏิทิน" → น้อง PP ถามแบบ (ระบุว่าเป็นแบบที่นิยม) → รู้แบบแล้ว **ส่งรูปตารางของแบบนั้น 1 รูป** + ถามขนาด/จำนวนรวดเดียว → ตอบราคาต่อชุด + รวม
- ลูกค้าในโหมด AI พูดถึง "บัตร PVC" → **ส่งรูปตารางทันที** + ถามจำนวน → ตอบราคาต่อใบ + รวม (บวกค่าออกแบบ 300 อัตโนมัติถ้า < 30 ใบ)
- จำนวนไม่ตรงขั้น → **เกลี่ยเชิงเส้นระหว่างสองขั้น** (คุณนุ๊ก) · **เกินขั้นสูงสุด → ส่งต่อทีมงาน** · **ต่ำกว่าขั้นแรก → แจ้งขั้นต่ำ** (คุณนุ๊ก)
- นอกโหมด: ถ้าข้อความแรกมีคำว่า PVC/ปฏิทิน ปุ่มเข้าโหมดพกชื่อสินค้าไปด้วย → **กดครั้งเดียว** เข้าโหมดแล้วน้อง PP ตอบต่อจากคำนั้นทันที (ไม่ต้องพิมพ์ซ้ำ)
- ตัวเลขทุกตัวมาจากแหล่งเดียว (calc API) เหมือนสินค้าอื่น — ไม่มีราคาฝังใน prompt
- ใช้ได้ทั้ง LINE และ Messenger · staff panel `/quote-assistant` เห็นว่าเทิร์นนั้นส่งตารางไหน

**Non-goals (รอบนี้ไม่ทำ)**
- ไม่เพิ่มปฏิทิน/PVC ในหน้า UI ของ calc.penprinting.co (API-only เหมือนนามบัตร — ทีมมีรูปตารางอยู่แล้ว) ← **Claude เลือก**
- ไม่ส่งรูปนอกโหมด AI (คุณนุ๊กตัดสิน)
- ไม่ตีราคาขนาด/แบบนอกตาราง — ส่งต่อทีมงาน (คุณนุ๊ก: "ขนาดอื่นๆ ต้องให้ทีมงานคุยอีกที")
- ไม่เพิ่มข้อความระยะเวลาผลิต/คิวปีใหม่ (ไม่ได้คุย — ถ้าอยากได้เป็นงานต่างหาก)

**Anti-goals (ถ้าเกิดถือว่าพัง)**
- น้อง PP เดาราคาขนาดอื่น หรือเกินตารางแล้วลากเส้นต่อเอง
- ส่งรูปตารางซ้ำทุกเทิร์น
- ตัวเลขในรูปกับตัวเลขในโค้ดไม่ตรงกัน (ดู §8 update protocol)
- บอทส่งรูปแทรกกลางแชตที่ทีมงานกำลังคุยกับลูกค้า

## 3. ข้อจำกัด / ของเดิมที่ต้องเคารพ

- สถาปัตยกรรมเดิม: น้อง PP มี tool เดียว `compute_quote` → POST calc `/api/quote` (single source of truth) · ProductType ปัจจุบัน `brochure | book | notebook | namecard` · นามบัตร (2026-07-13) คือแบบอย่าง "ตารางราคาคงที่ ไม่มีสูตรกระดาษ"
- LINE reply API: ≤5 messages/reply · image message = `{type:'image', originalContentUrl, previewImageUrl}` ทั้งคู่ HTTPS, JPEG/PNG, original ≤10 MB, preview ≤1 MB · quick reply label **≤20 ตัวอักษร**
- Messenger: 1 message/call → ส่งรูปแล้วค่อยส่งข้อความตามลำดับ (`attachment:{type:'image', payload:{url, is_reusable:true}}`)
- `ChannelAdapter.reply()` ปัจจุบันรับ 1 message — ต้องขยายให้รับ array (LINE: `messages:[...]` quick reply ติดตัวสุดท้าย · Messenger: loop sequential)
- นอกโหมด: hint ≤1 ครั้ง/คน/24 ชม. + ไม่แทรกถ้าทีมงานตอบใน 48 ชม. (HINT-1) — **ใช้ gate เดิมทั้งหมด** แค่เปลี่ยนปุ่ม
- History ที่ส่งให้ model มีแค่ role+text (ไม่มี tool call) → การ "ไม่ส่งรูปซ้ำ" ต้องอาศัยข้อความของน้อง PP เองที่บอกว่าส่งแล้ว (§6.4)
- วลี "ส่งต่อทีมงาน" เป็น load-bearing (detectCustomerEscalation) — การส่งต่อกรณีเกินตาราง/ขนาดอื่นต้องใช้วลีนี้
- Repo convention: TDD RED-first · calc ไม่มี unit test ใช้ `scripts/smoke-baselines.json` เป็น RED→GREEN และ **pin ทุก output field** (บทเรียน SPOT UV 2026-10-02) · deploy calc ก่อน dashboard
- `public/` ของ dashboard เสิร์ฟสาธารณะ (ยืนยัน `curl` 200 ไม่ติด middleware) → โฮสต์รูปที่นี่ได้

## 4. ประสบการณ์ลูกค้า (ตัดสินแล้ว)

### 4.1 ในโหมด AI — ปฏิทิน
```
ลูกค้า:  ทำปฏิทินไหมคะ
น้อง PP: ทำได้ค่ะ 😊 แบบที่นิยมมี 3 แบบ: ปฏิทินจีน · ตั้งโต๊ะ 6x8 นิ้ว · แขวน
         รับแบบไหนดีคะ (ขนาดอื่นนอกจากนี้ ทีมงานคุยรายละเอียดให้ค่ะ)
ลูกค้า:  แขวน
น้อง PP: [รูปตารางปฏิทินแขวน]
         📊 ตารางราคาปฏิทินแขวนอยู่ด้านบนนะคะ
         ขนาด 10.5x15 หรือ 15x21 นิ้ว และกี่ชุดดีคะ
ลูกค้า:  15x21 800 ชุด
น้อง PP: 💰 ปฏิทินแขวน 15x21 นิ้ว 800 ชุด → ชุดละ 20.25 บาท · รวม 16,200 บาท (ยังไม่รวม VAT 7%)
         📋 1 ชุด = หัวป้ายโฆษณา 1 แผ่น + แผ่นเดือน 13 แผ่น
         ราคาประเมินเบื้องต้นนะคะ ทีมงานยืนยันราคาอีกครั้งค่ะ 🙏
```
- ถ้าลูกค้าบอกแบบมาตั้งแต่แรก ("ปฏิทินแขวนราคาเท่าไหร่") → ข้ามคำถามแบบ ส่งรูป + ถามขนาด/จำนวนเลย
- ถ้าบอกครบในข้อความเดียว ("ปฏิทินตั้งโต๊ะ 14 แผ่น 500 ชุด") → ส่งรูป + ตอบราคาในเทิร์นเดียว
- **ขนาดต้องถามเสมอ ห้ามเดา** (ราคาต่างกันเกือบ 2 เท่า) — ถามรวมกับจำนวนครั้งเดียว
- ขนาด/แบบอื่น ("ปฏิทินแขวน A3", "ปฏิทินโปสเตอร์") → ส่งต่อทีมงาน (วลี pin)

### 4.2 ในโหมด AI — บัตร PVC
```
ลูกค้า:  บัตร PVC ราคาเท่าไหร่
น้อง PP: [รูปตาราง PVC]
         📊 ตารางราคาบัตร PVC อยู่ด้านบนนะคะ
         ต้องการกี่ใบดีคะ
ลูกค้า:  20 ใบ
น้อง PP: 💰 บัตร PVC 20 ใบ → ใบละ 90 บาท · ค่าออกแบบ 300 บาท (ต่ำกว่า 30 ใบ) · รวม 2,100 บาท (ยังไม่รวม VAT 7%)
         📋 ขนาด 5.4x8.6 ซม. พิมพ์หน้าเดียวหรือสองหน้าราคาเดียวกัน ทนน้ำ ทนรอยขีดข่วน
         ราคาประเมินเบื้องต้นนะคะ ทีมงานยืนยันราคาอีกครั้งค่ะ 🙏
```
- ≥30 ใบ → ออกแบบฟรี ไม่ต้องมีบรรทัดค่าออกแบบ

### 4.3 ขอบตาราง
- **เกินขั้นสูงสุด** (แขวน >5,000 · ตั้งโต๊ะ >3,000 · จีน >2,000 · PVC >1,000) → น้อง PP **ไม่ตีราคา** ส่งต่อทีมงาน (วลี pin, จบบทสนทนาตามกฎเดิม)
- **ต่ำกว่าขั้นแรก** — เกิดเฉพาะปฏิทินจีน (<300) → บอกว่า "ปฏิทินจีนขั้นต่ำ 300 ชุดค่ะ" แล้วถามว่าจะเอา 300 ไหม (ยังคุยต่อได้ ไม่ใช่ส่งต่อ)

### 4.4 นอกโหมด AI — ชี้ทางให้เข้าโหมด (ต่างกันตามช่องทาง)
**ข้อเท็จจริงจากระบบเดิม (builder-check 2026-10-19):** hint นอกโหมดบน **LINE ปิดถาวร** ตั้งแต่ HINT-1 (2026-07-10) เพราะ LINE OA Manager ตอบลูกค้าโดยไม่มี webhook → บอทตรวจไม่ได้ว่าทีมกำลังคุยอยู่ → ห้ามแทรก. ทางเข้าโหมด AI ของ LINE = **ปุ่ม rich menu** (postback `ai_quote_start`) → INTRO. มีแค่ **Messenger** ที่ hint เปิดอยู่ (มี staff-echo คุ้มกัน). งานนี้**ไม่กลับคำตัดสิน HINT-1** — ถ้าจะเปิด hint LINE ต้องเป็นงานแยก

- **LINE**: นอกโหมดบอทเงียบเหมือนเดิม (ทีมตอบเอง) · ลูกค้ากด rich menu → INTRO (list สินค้า 6 ชนิดแล้ว) → พิมพ์ "บัตร PVC" / "ปฏิทิน" → เข้า §4.1/§4.2 ทันที — ไม่มีของใหม่นอกโหมดบน LINE
- **Messenger** (hint ผ่าน gate 24h/48h เดิมทั้งหมด): ข้อความแรกของลูกค้า
  - มีคำว่า PVC → hint เดิม แต่ปุ่ม = **"🤖 ดูราคาบัตร PVC"** (payload `ขอราคา AI บัตร PVC`)
  - มีคำว่า ปฏิทิน → ปุ่ม = **"🤖 ดูราคาปฏิทิน"** (`ขอราคา AI ปฏิทิน`)
  - ไม่มีทั้งคู่ → ปุ่มเดิม "🤖 เริ่มขอราคา AI"
  - กดปุ่มที่พกชื่อสินค้า → เข้าโหมด **แล้วรันเทิร์นแรกด้วยคำนั้นทันที** (แทน INTRO) → ลูกค้าได้รูป + คำถามจำนวน/แบบ ในจังหวะเดียว · ท้ายข้อความเทิร์นแรกนี้ต่อบรรทัด "(พิมพ์ 'ออก' เมื่อต้องการกลับไปคุยกับทีมงานค่ะ)" เพราะลูกค้าไม่ได้เห็น INTRO ← **Claude เลือก**
- ข้อความชี้ทาง/ต้อนรับ/template "ขอราคาหน่อย" ทุกจุดที่ list สินค้า → เพิ่ม **ปฏิทิน · บัตร PVC** (จาก 4 → 6 ชนิด) — ทั้ง LINE และ Messenger

### 4.5 Staff panel `/quote-assistant`
พนักงานถามน้อง PP เหมือนลูกค้า → ได้ตัวเลขเดียวกัน · ถ้าเทิร์นนั้นส่งตาราง panel แสดงลิงก์/thumbnail รูปนั้น (ให้พนักงานกดเปิดส่งต่อลูกค้าเองได้)

## 5. ข้อมูลราคา (คุณนุ๊ก 2026-10-19 — **ก่อน VAT ทุกตัว**)

### 5.1 ตาราง (ตรงกับรูป 4 ใบ)
**ปฏิทินจีน** — 1 ชุด = 13 แผ่น · ขั้นต่ำ 300 ชุด · บาท/ชุด

| จำนวน | 10.5x15 นิ้ว | 15x21 นิ้ว |
|---|---|---|
| 300 | 35 | 65 |
| 500 | 22 | 40 |
| 1,000 | 17 | 27 |
| 2,000 | 13.5 | 22.5 |

**ปฏิทินตั้งโต๊ะ 6x8 นิ้ว** — รวมฐานตั้ง + สันห่วงแล้ว · บาท/ชุด

| จำนวน | 8 แผ่น 16 หน้า | 14 แผ่น 28 หน้า |
|---|---|---|
| 1-100 | 145 | 250 |
| 200 | 85 | 150 |
| 300 | 60 | 110 |
| 500 | 45 | 75 |
| 1,000 | 30 | 45 |
| 1,500 | 28 | 43 |
| 2,000 | 26 | 40 |
| 3,000 | 24 | 35 |

**ปฏิทินแขวน** — 1 ชุด = หัวป้ายโฆษณา 1 แผ่น + แผ่นเดือน (พู่) 13 แผ่น · บาท/ชุด

| จำนวน | 10.5x15 นิ้ว | 15x21 นิ้ว |
|---|---|---|
| 1-100 | 40 | 60 |
| 200 | 35 | 40 |
| 300 | 24 | 30 |
| 500 | 15 | 22 |
| 1,000 | 10.5 | 19 |
| 1,500 | 9 | 17.5 |
| 2,000 | 8 | 16.5 |
| 3,000 | 7.25 | 15.5 |
| 4,000 | 6.75 | 14.5 |
| 5,000 | 6.25 | 13 |

**บัตร PVC** — 5.4x8.6 ซม. · พิมพ์หน้าเดียว/สองหน้าราคาเดียวกัน · ทนน้ำ ทนรอยขีดข่วน · บาท/ใบ

| จำนวน | บาท/ใบ |
|---|---|
| 1-9 | 150 |
| 10-99 | 90 |
| 100 | 75 |
| 200 | 65 |
| 500 | 60 |
| 1,000 | 39 |

ค่าออกแบบ: **≥30 ใบ ฟรี · <30 ใบ +300 บาท** (ค่าคงที่ต่อออเดอร์ บวกเข้าราคารวม)

### 5.2 กฎคำนวณ
1. แถวที่เป็น **ช่วง** (1-100, 1-9, 10-99) = ราคาคงที่ทั้งช่วง
2. ระหว่าง**จุด**สองจุดที่อยู่ติดกัน (รวมปลายช่วง → จุดถัดไป เช่น 100→200) = **เกลี่ยเชิงเส้น** ตามจำนวน (คุณนุ๊ก)
3. ราคาต่อหน่วยที่เกลี่ยแล้ว **ปัดขึ้นเป็นขั้น 0.25 บาท** (ceil) — **คุณนุ๊กเคาะ 2026-10-19** (ตารางใช้ .25/.5/.75 อยู่แล้ว; ตัวเลขที่ตรงขั้นไม่เปลี่ยน)
4. `totalPrice = qty × unitPrice (+ designFee ถ้า PVC <30)` · `unitPriceVat/totalPriceVat` = ×1.07 ตาม convention
5. qty **> จุดสุดท้าย** → calc ตอบ **422** พร้อม message "จำนวนเกินตารางราคา — ส่งต่อทีมงานประเมิน" (recoverable → model ส่งต่อด้วยวลี pin)
6. qty **< จุดแรก** (ปฏิทินจีน <300) → **422** message "ปฏิทินจีนขั้นต่ำ 300 ชุด" (recoverable → model แจ้งขั้นต่ำ ถามต่อ)
7. ตัวอย่างตรวจทาน (ใช้เป็น baseline): แขวน 15x21 800 ชุด → 22 − 3×(300/500) = 20.2 → **20.25** รวม **16,200** · PVC 150 ใบ → **70** รวม **10,500** (ไม่มีค่าออกแบบ) · PVC 20 ใบ → 90 + ออกแบบ 300 → รวม **2,100** · ตั้งโต๊ะ 14 แผ่น 1,000 ชุด → 45 รวม 45,000 · จีน 10.5x15 300 ชุด → 35 รวม 10,500 · จีน 200 → 422 ขั้นต่ำ · แขวน 6,000 → 422 เกินตาราง

## 6. สถาปัตยกรรม (ตัดสินแล้ว — ตามรอยนามบัตร)

### 6.1 calc (`print-calculator-next`) — แหล่งราคา
- ProductType ใหม่ 2 ตัวใน `/api/quote`: **`calendar`** และ **`pvccard`**
  - `calendar` spec: `{ kind: 'chinese' | 'desk' | 'hanging', variant, qty }` — variant: chinese/hanging = `'10.5x15' | '15x21'`, desk = `'8' | '14'` (จำนวนแผ่น) · result: `{ kind, variant, qty, unitPrice, totalPrice, unitPriceVat, totalPriceVat, sheetsPerSet }` (sheetsPerSet: จีน 13 · แขวน 14 = หัว 1 + เดือน 13 · ตั้งโต๊ะ 8/14)
  - `pvccard` spec: `{ qty }` · result: `{ qty, unitPrice, designFee, totalPrice, unitPriceVat, totalPriceVat }`
- ตารางอยู่ใน `DEFAULT_CONFIG` (defaults.ts) เหมือน `namecard` · types.ts / quote-schema.ts (zod) / calc.ts (compute) / route.ts (switch) ครบชุด
- helper เกลี่ย+ปัด เขียนครั้งเดียวใช้ทั้ง 4 ตาราง
- 422 สองกรณี (§5.2 ข้อ 5-6) คืน `{ error, message, productType }` รูปแบบเดียวกับ "infeasible" ของกล่อง
- **smoke baselines** เพิ่มเคสครบทุกตาราง + เคสเกลี่ย + PVC ทั้งสองฝั่ง 30 + เคส 422 ทั้งสอง (ถ้า smoke-core รองรับ expect status — ถ้าไม่ รอบนี้เพิ่มให้รองรับ) — pin `unitPrice`, `totalPrice`, `designFee`, `sheetsPerSet`
- CLAUDE.md ของ calc: บันทึกสินค้าใหม่ + กฎเกลี่ย + "ราคาเปลี่ยน = รูป + defaults + baselines คอมมิตเดียว"

### 6.5 dashboard — นอกโหมด (Messenger เท่านั้น): ปุ่มพกสินค้า + เข้าโหมดแล้วรันต่อ
- `customer-triggers.ts`: `detectPriceTableTopic(text): 'pvc' | 'calendar' | null` (pure) — PVC: `/pvc|พีวีซี|บัตรพลาสติก/i` · ปฏิทิน: `/ปฏิทิน/` · ปุ่ม 2 แบบใหม่ label ≤20 ตัวอักษร (§4.4) · ใช้เฉพาะจุดที่ hint ยิง (ซึ่งปัจจุบันคือ Messenger — LINE flag ปิด จึงไม่ถึงโค้ดนี้โดยอัตโนมัติ ไม่ต้องเขียน channel check เพิ่ม)
- entry keyword: **ฟอร์มพก seed ต้องมี token "AI" เสมอ** — `^\/?(ขอราคา|ตีราคา)\s*ai\s+(.+)$` → route `enter-ai` พก `seed` (เฉพาะข้อความที่ปุ่มสร้างเท่านั้น) · ฟอร์มเปล่าเดิม `^\/?(ขอราคา|ตีราคา)(\s*ai)?$` **ไม่เปลี่ยน** · ประโยคธรรมชาติ "ขอราคา ปฏิทิน 500 ชุด" (ไม่มี AI) ต้อง**ไม่**เข้าโหมด — เหมือนเดิม (route `enter-ai` ข้าม gate 24h/48h ดังนั้นห้ามเปิดกว้าง — anti-goal "แทรกกลางแชตทีม") ← **Claude เลือก (builder-check ข้อ 2)**
- มี seed → `enterMode` แล้วเดินทาง `ai` ด้วย `text = seed` (สร้าง session / rate limit / triggers ตามปกติ) + ต่อบรรทัด "ออก" ท้าย reply เทิร์นนี้ (§4.4) · ไม่มี seed → INTRO_TEXT เหมือนเดิม
- postback `ai_quote_start` (LINE rich menu + Messenger menu) ไม่เปลี่ยน

## 7. สิ่งที่ปล่อยให้ builder ตัดสิน
- โครงข้อมูลตาราง (array ของจุด/ช่วง) และชื่อ helper · ชื่อไฟล์/เทสต์ · regex รายละเอียด

- polish หน่วยบนการ์ด escalation · รูปแบบ thumbnail บน panel
- ข้อความ 422 ตรงตัว (ให้ความหมายตาม §5.2)

## 8. Update protocol — ราคาเปลี่ยน
ราคาปฏิทิน/PVC เปลี่ยน = **คอมมิตเดียว** แก้ครบ 3 ที่: รูปใน `public/price-tables/` (คุณนุ๊กส่งรูปใหม่) + `DEFAULT_CONFIG` ใน calc + `smoke-baselines.json` — ไม่งั้นลูกค้าเห็นรูปเลขหนึ่ง น้อง PP ตอบอีกเลข (anti-goal) · บันทึกใน calc CLAUDE.md + PATTERNS
