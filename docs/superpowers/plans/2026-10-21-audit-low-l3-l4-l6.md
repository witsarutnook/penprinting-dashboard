## Task 1 — L3: slip-verify card footer must not claim "ตรวจสอบอัตโนมัติ" on error/unreadable

**Files:** `lib/ai-quote/slip-flex.ts`, `tests/ai-quote-slip-flex.test.ts`

**Problem.** `buildSlipFlex()` (`lib/ai-quote/slip-flex.ts` ~line 157-160) renders the footer text `'✓ ตรวจสอบอัตโนมัติ · Penprinting'` for every `SlipState`, including `'error'` (ระบบขัดข้องชั่วคราว) and `'unreadable'` (อ่านสลิปไม่ได้). A card whose header says the automatic check failed must not carry a footer saying "✓ checked automatically".

- States `'success' | 'duplicate' | 'mismatch'` (a verdict was produced): footer text stays exactly `'✓ ตรวจสอบอัตโนมัติ · Penprinting'` (unchanged).
- States `'unreadable' | 'error'` (no verdict): footer text becomes exactly `'รอทีมงานตรวจสอบ · Penprinting'` (no leading ✓). Keep the same footer box layout/color (`ACCENT`), only the text changes. Every state must still carry the word `Penprinting` and must never contain `Thunder`/`ธันเดอร์`.

**Tests (RED first).** In `tests/ai-quote-slip-flex.test.ts`:
- Split the existing test `'every state carries the Penprinting footer (not Thunder branding)'` (currently asserts `toContain('ตรวจสอบอัตโนมัติ')` on the success fixture) into:
  1. `'verdict states (success/duplicate/mismatch) carry the "✓ ตรวจสอบอัตโนมัติ · Penprinting" footer'` — build all three states and assert each JSON contains `'✓ ตรวจสอบอัตโนมัติ · Penprinting'`.
  2. `'non-verdict states (unreadable/error) carry the "รอทีมงานตรวจสอบ · Penprinting" footer and never "✓ ตรวจสอบอัตโนมัติ"'` — build an `'unreadable'` result and an `'error'` result (use the same fixture shapes the file already uses for those two states; `classifySlipState` decides via `slipFailureKind`), assert each contains `'รอทีมงานตรวจสอบ · Penprinting'` and does **not** contain `'✓ ตรวจสอบอัตโนมัติ'`. ## Task 2 — L4: one date parser for LINE `/track` card and web (Bangkok TZ for ISO-with-time, quote-unwrap, pad)

**Files:** `lib/jobs.ts`, `lib/ai-quote/track-flex.ts`, `tests/jobs-display-date.test.ts`, `tests/ai-quote-track-flex.test.ts`

**Problem.** Two independent date parsers render the same order differently:
- `lib/ai-quote/track-flex.ts` `cleanDate_()` (~line 324-351): regex-extracts `DD/MM/YYYY` anywhere in the string (pads), else `new Date()` + `Intl.DateTimeFormat('en-GB', {timeZone:'Asia/Bangkok'})`. Empty → `'-'`. Does **not** unwrap the legacy `"…"` quote wrapper, so a Sheet-era cell like `'"2026-05-07T17:00:00.000Z"'` renders raw with quotes on the LINE card.
- `lib/jobs.ts` `displayDate()` (~line 61-99) used by the web `/track` via `displayDatePadded()`: unwraps quotes, but its ISO branch `^(\d{4})-(\d{1,2})-(\d{1,2})` takes the date part **without timezone conversion**, so `2026-05-07T17:00:00.000Z` (= 2026-05-08 00:00 Bangkok, how Google Sheets serialised a Bangkok-midnight Date) shows **7/5/2026** on the web while LINE shows **08/05/2026**. Its `dmy` regex is anchored (`$`), so `21/4/2026 10:00` falls to `new Date()`, which is invalid for D/M/Y → returned raw and unpadded.

Date columns are `TEXT` in Postgres (`app/api/admin/db-migrate/route.ts`), so all of these legacy shapes exist in prod rows; new rows written by the dashboard are date-only `YYYY-MM-DD` (from `getBangkokToday()` / the date input) and must render unchanged.

**Required behaviour (single source of truth = `displayDate` in `lib/jobs.ts`).**
1. ISO **with a time component** (`YYYY-MM-DDTHH:MM…` with `Z`/offset, or any string `new Date()` parses that is not date-only) → convert to **Asia/Bangkok** calendar date. `displayDate('2026-05-07T17:00:00.000Z') === '8/5/2026'`; `displayDatePadded('"2026-05-07T17:00:00.000Z"') === '08/05/2026'` (quote-unwrap already exists, keep it).
2. ISO **date-only** (`YYYY-MM-DD`, no time) → unchanged, no TZ shift: `displayDate('2026-09-05') === '5/9/2026'`, `displayDatePadded('2026-09-05') === '05/09/2026'`.
3. `D/M/YYYY` or `DD/MM/YYYY` with a trailing suffix (time or anything after whitespace), e.g. `'21/4/2026 10:00'` → take the date portion: `displayDate('21/4/2026 10:00') === '21/4/2026'`, `displayDatePadded('21/4/2026 10:00') === '21/04/2026'`. (Pure `DD/MM/YYYY` keeps working as today.)
4. Everything already pinned in `tests/jobs-display-date.test.ts` keeps passing (see Global Constraints).
5. `cleanDate_()` in `track-flex.ts` becomes a thin delegate: `return displayDatePadded(d == null ? '' : String(d))` — delete the private regex/Intl implementation. Consequences to accept: empty/missing dateIn/dateDue on the LINE card now render `'—'` (same glyph as the web `/track`) instead of `'-'`. **Ruling (controller):** aligning on `'—'` is intended; do not special-case `'-'` back in.

**Tests (RED first).**
- `tests/jobs-display-date.test.ts` — add:
  - `'converts ISO timestamps to the Asia/Bangkok calendar date'`: `displayDate('2026-05-07T17:00:00.000Z')` → `'8/5/2026'`; `displayDatePadded('"2026-05-07T17:00:00.000Z"')` → `'08/05/2026'`; and an in-offset sample `displayDate('2026-05-08T00:00:00+07:00')` → `'8/5/2026'`.
  - `'leaves date-only ISO untouched (no timezone shift)'`: `displayDate('2026-09-05')` → `'5/9/2026'`, `displayDate('2026-01-01')` → `'1/1/2026'`.
  - `'takes the date portion of DD/MM/YYYY followed by a time'`: `displayDate('21/4/2026 10:00')` → `'21/4/2026'`, `displayDatePadded('21/4/2026 10:00')` → `'21/04/2026'`.
  - Expected RED: the first and third fail (today: `'7/5/2026'` and `'21/4/2026 10:00'`).
- `tests/ai-quote-track-flex.test.ts` — add one test `'renders legacy Sheet-era dates through the shared displayDatePadded parser'`: a `TrackState` whose `order.dateIn` is `'"2026-05-07T17:00:00.000Z"'` and `order.dateDue` is `'21/4/2026 10:00'`; assert the JSON of `buildOrderFlex(...)` contains `'08/05/2026'` and `'21/04/2026'`, and does not contain `'"2026-05-07'`. Add a second small test `'empty dates render as — (same as web /track)'`: `dateIn: ''`, `dateDue: undefined` → JSON contains `'—'`. Expected RED: first fails on the raw quoted string; second fails because `cleanDate_` returns `'-'`.
- Use `'2026-05-07T17:00:00.000Z'` style fixtures only; **do not** make tests depend on the machine timezone (all conversions must go through `timeZone: 'Asia/Bangkok'`).

**Implementation sketch (`lib/jobs.ts` `displayDate`).**
- Keep the quote-unwrap.
- Match date-only ISO strictly: `/^(\d{4})-(\d{1,2})-(\d{1,2})$/` → d/m/y as now.
- Match `dmy` with optional suffix: `/^(\d{1,2})\/(\d{1,2})\/(\d{4})(?:\s.*)?$/` → d/m/y.
- Everything else (ISO with time, `Date.toString()` output, etc.) → existing `new Date()` + `Intl.DateTimeFormat('en-GB', { timeZone: 'Asia/Bangkok', day:'numeric', month:'numeric', year:'numeric' })` fallback (already present). Invalid → return the string unchanged (as today).
- Update the JSDoc above `displayDate` to describe the ISO-with-time → Bangkok rule.
- `track-flex.ts`: `import { displayDatePadded } from '@/lib/jobs';` and reduce `cleanDate_` to the one-line delegate (keep the function name so the two call sites and the Step-6 change in Task 3 keep reading naturally). Check `lib/jobs.ts` has no `server-only` import that would break the Flex module in tests — it is already imported by `lib/track-result.ts` which is tested, so it is safe.

**Blast radius to verify.** `displayDate` is called from staff screens (`app/archive/page.tsx`, `app/board/card.tsx`, `app/shipped/list-client.tsx`, `app/orders/orders-table.tsx`, `app/orders/client.tsx`, `app/orders/[id]/print/page.tsx`, `components/board/kpi-detail-modal.tsx`). The only behaviour change for them is legacy ISO-with-time rows moving to the correct Bangkok day and `D/M/YYYY HH:MM` losing the time suffix (those screens use `displayDateTime` when they want time). Run the **full** suite and `npm run type-check`; report any failure by name.

## Task 3 — L6: LINE `/track` card shows the shipped date on the final step, like the web

**Files:** `lib/ai-quote/track-flex.ts`, `tests/ai-quote-track-flex.test.ts`

**Problem.** `buildSteps_` step 6 (`track-flex.ts` ~line 264-266) always renders `makeStep_(…, 'จัดส่งเรียบร้อยแล้ว', 'Order complete')`. The web (`app/track/client.tsx` ~line 315-318) renders `จัดส่งเรียบร้อยแล้ว (DD/MM/YYYY)` when the order is shipped and `shippedDate` is known (`lib/track-result.ts:141` → `displayDatePadded(shipped.shippedDate)`). `TrackState.shipped` already carries the Postgres `shipped` row (`Shipped.shippedDate: string` in `lib/types.ts`, set with `formatThaiDate()` on move-to-shipped), but the Flex card never reads it.

**Required behaviour.**
- When `isShipped` and `state.shipped?.shippedDate` renders to a date (i.e. `displayDatePadded(...)` returns something other than `'—'`), step 6 Thai label is `'จัดส่งเรียบร้อยแล้ว (DD/MM/YYYY)'` — exact same format as the web. English label stays `'Order complete'`.
- When shipped but no/empty `shippedDate`, or not shipped: label stays `'จัดส่งเรียบร้อยแล้ว'` (unchanged — the existing test `'renders a shipped order as delivered'` uses `shipped: {}` and must keep passing).
- The status badge text (`badgeLabel = 'จัดส่งเรียบร้อยแล้ว'`) is **not** changed — only the step-6 row.

**Tests (RED first).** In `tests/ai-quote-track-flex.test.ts` add `'shows the shipped date on the final step, matching the web /track'`: state `{ order: {...}, job: { dept: 'post', date: '10/06/2026' }, shipped: { shippedDate: '15/6/2026' }, cancelled: null }` → JSON contains `'จัดส่งเรียบร้อยแล้ว (15/06/2026)'`. Add `'omits the date when the shipped row has none'`: `shipped: {}` → JSON contains `'จัดส่งเรียบร้อยแล้ว'` and does not contain `'จัดส่งเรียบร้อยแล้ว ('`. Expected RED: the first fails.

**Implementation.** `buildSteps_` needs access to the shipped row: pass `shippedDate` (already formatted via `cleanDate_` from Task 2, i.e. `displayDatePadded`) into `buildSteps_` from `buildOrderFlex` (add a parameter; do not widen `TrackState` types beyond `shipped: { shippedDate?: string; [k: string]: unknown } | null`). Compute `const shipThai = isShipped && shippedDate !== '—' ? \`จัดส่งเรียบร้อยแล้ว (${shippedDate})\` : 'จัดส่งเรียบร้อยแล้ว';`.
